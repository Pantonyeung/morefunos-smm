# More Fun SMM｜組合架構與介面來源規格 V1

## 0. 文件目的

本文件鎖定 More Fun SMM 的產品來源、介面來源、功能來源及頁面分布。

SMM 不會直接複製任何一個現有系統，而是由三個來源組合：

1. More Fun App／Customer Web：提供手機介面、商品瀏覽、商品詳情、購物車及確認訂單流程。
2. More Fun Ordering Web：提供目前實際對客銷售流程、手機安全區、分類、商品卡、購物車、結帳與返回選購體驗。
3. SMT：提供正式營運功能、訂單能力、堂食、售罄、報表、付款、打印工作、訂單身份及營運頁面分布。

最終產品定義：

> More Fun SMM = Customer Web 手機操作方式 + More Fun App 品牌介面 + SMT 完整營運能力。

---

## 1. 來源權威順序

### 1.1 商業規則與資料權威

由高至低：

1. SMT 最新正式 Domain／中央 API／資料模型
2. 已鎖定 More Fun 商業規則
3. Customer Web 現有實作
4. 舊 SMM Runtime 或舊前端內嵌規則

Customer Web 只可作為手機流程與既有顧客體驗參考，不可取代 SMT 最新規則。

### 1.2 UI／UX 來源

- 手機操作模式：以 More Fun App／Customer Web 為主。
- 營運頁面結構：以 SMT 為主。
- 品牌語言、暖感、視覺調性：沿用 More Fun 前端。
- 高峰操作效率、訂單狀態、付款、售罄與打印：以 SMT 為主。

## 2. 核心組合原則

### 2.1 SMM 不是縮小版 SMT

不可直接將 SMT 平板橫向三欄介面縮細。

禁止：

- 長期顯示右側購物車
- 一頁同時塞商品、訂單、付款、打印
- 將 SMT 表格直接縮成手機版
- 將所有功能放入同一個「更多」頁

### 2.2 SMM 不是 Customer Web 複製版

Customer Web 對客，SMM 對內營運，因此必須新增：

- 訂單來源
- 付款確認
- 堂食桌號
- 暫存／預約
- 訂單修改
- 退款／取消
- 售罄
- 報表
- 打印工作
- 訂單身份與流水
- 系統狀態

### 2.3 手機點單採購物網站流程

正式流程：

```text
餐牌
→ 商品詳情／配置
→ 加入購物車
→ 繼續選購
→ 購物車核對
→ 確認訂單
→ 付款／來源／堂食資料
→ 正式建立訂單
→ 建立打印工作
→ 顯示訂單與打印結果
```

## 3. SMM 主導航

底部主導航鎖定為：

```text
工作台｜點單｜訂單｜堂食｜更多
```

購物車不是主導航，而是點單流程內的功能入口。

### 3.1 工作台

提供：

- SMT 在線狀態
- 打印服務狀態
- 新訂單
- 待處理
- 可取餐
- 堂食使用中
- 暫存訂單
- 付款待核實
- 打印失敗
- 今日營業額
- 快速開單
- 快速售罄

### 3.2 點單

採用 Customer Web／More Fun App 的手機購物流程。

### 3.3 訂單

沿用 SMT 的營運能力，但改成手機卡片及分頁方式。

### 3.4 堂食

沿用 SMT 堂食能力，改成手機桌卡與逐步操作。

### 3.5 更多

包括：

- 售罄
- 預約
- 報表
- 付款對帳
- 打印工作
- 系統狀態
- 登入與設定

## 4. 點單頁面分布

### 4.1 `/menu`

介面參考 Customer Web：

- 頂部安全區
- 訂單來源快捷選擇
- 搜尋
- 分類橫滑
- 人氣推薦
- 兩欄商品卡
- 售罄狀態
- 商品簡稱／Advert Code
- 浮動購物車列

### 4.2 `/product/:id`

商品詳細配置：

- 商品名稱、圖片、價格
- 飯底
- 飯量
- 蛋
- 飯團
- 小食
- 飲品
- 冰量
- 甜度
- 醬汁
- 加購
- 備註
- 數量
- 加入購物車

所有選項由 SMT 最新規則控制。

### 4.3 `/cart`

購物車只負責核對商品：

- 商品
- 選項
- 數量
- 修改
- 刪除
- 備註
- 小計
- 優惠
- 外賣盒費
- 總額

主要操作：

```text
繼續選購｜確認訂單
```

返回選購時保留原分類及捲動位置。

### 4.4 `/checkout`

確認營運資料：

- 訂單來源
- 外賣／堂食
- 枱號
- 客人名稱
- 電話
- WhatsApp
- 取餐時間
- 預約日期
- 訂單備註
- 付款方式
- 混合付款
- 待核實

主要操作：

```text
返回修改｜暫存訂單｜確認落單
```

### 4.5 `/order-success`

顯示：

- 正式訂單編號
- SMT 接收狀態
- 打印工作狀態
- 各打印機結果
- 查看訂單
- 再開新單
- 補打
- 通知客人

### 5.2 唯一硬件限制

SMM 不直接連接打印機。

SMM 可以：

- 建立打印工作
- 首次打印
- 補打
- 重印
- 改送

- 取消未執行工作

- 重試失敗工作

SMT 負責：

- 接收中央 Print Job
- Android Bridge
- 實體打印
- 回傳真實狀態

## 6. More Fun App／Customer Web 視覺繼承

SMM 應保留：

- More Fun 輕日系現代簡約風格
- 溫暖但清晰的品牌語言
- iPhone／Android 安全區
- 大觸控範圍
- 清晰按壓反饋
- 商品卡、分類、詳情頁及購物車熟悉感
- 底部固定主操作
- 返回路徑清楚
- Loading／錯誤狀態品牌化

但營運頁面要比 Customer Web 更直接：

- 減少裝飾動畫
- 提高資訊密度
- 高峰模式優先
- 錯誤、付款、售罄、打印狀態要更明顯

## 8. 登入與權限

- 主要使用者：店主太太
- 其他人：由店主現場授權
- 登入：名稱＋密碼
- 登入後：全部營運功能開放
- V1 不設角色分級
- V1 不設細項權限鎖
- 密碼、Token、Firebase Secret、打印機 IP 不可寫入 GitHub

## 10. 不可偏離事項

- 不可將 SMM 變成簡化 Admin。
- 不可只做查單及報表。
- 不可移除完整點單能力。
- 不可移除堂食。
- 不可移除付款確認。
- 不可移除售罄。
- 不可移除退款、取消及修改訂單。
- 不可讓 SMM 直接連打印機。
- 不可用 Customer Web 舊內嵌規則覆蓋 SMT 最新規則。
- 不可未完成資料及狀態邊界就開始大量 UI 實作。
